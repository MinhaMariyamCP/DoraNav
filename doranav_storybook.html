CHAPTER 01 02
CHAPTER 01

Dora Needed a Way Out

It started with a surprisingly simple problem: Dora has places to go, but she does not really have a navigation system. While scrolling through Instagram, we came across a Reporter Live post asking whether Dora was actually blind. Instead of simply scrolling past it, we started wondering what it would look like if Dora actually had a system that could guide her through her world.

TinkerHub's Useless Projects 3.0 gave us the perfect excuse. We initially approached the problem like a miniature Google Maps: give Dora a map, let her select a destination, calculate a route, and guide her there.

The first solution was straightforward: create a custom map of Dora's world with important destinations connected through navigable paths. That sounded reasonable.

⚠️ Unfortunately, we kept thinking.
Stage 1: The Interactive World Map UI 🗺️
CHAPTER 02 03
CHAPTER 02

A Map Alone Wasn't Enough

Once we started designing the map, we realised that simply displaying locations would not actually solve the navigation problem. A static map can show Dora where places are, but it cannot tell her what to do when the world changes.

So we pivoted from building a map interface to building a real navigation system. We created a custom Dora world containing destinations, intermediate locations, roads, bridges, rivers, and mountains.

📐 Transformation to Graph Structure:
  • • Locations → Mathematical Nodes with coordinates (x, y)
  • • Roads & Rivers → Directed Weighted Graph Edges
  • • Path Properties → Distance, Difficulty, Safety, Swiper Risk

Instead of treating these as drawings on a screen, we represented them as structured navigation data. This gave us something much more useful than a pretty map: we had a world that could actually be processed by an algorithm.

3D Graph World: Nodes, Edges & Biomes 🌐
CHAPTER 03 04
CHAPTER 03

How Does Dora Find the Best Route?

The next problem was obvious: once we had a connected world, how would Dora actually find her way from one location to another? Hard-coding a route for every destination would have been easy, but it would not really be navigation.

We needed an algorithm that could inspect available paths and calculate the optimal route dynamically. We approached the problem using graph-based pathfinding and selected A* (A-Star).

📐 The A* Heuristic Formula:
f(n) = g(n) + h(n)
• g(n) = Exact travel cost incurred from start location
• h(n) = Estimated Euclidean distance to the destination

"At this point, the project had officially gone from 'Let's make Google Maps for Dora' to 'Okay, now we need to implement A*.'
Orpichu A* mathiyenn 😂"

The Route Cannot Be the Same Every Time

A single shortest path was still not enough because Dora's journeys were supposed to feel different depending on what she wanted from the adventure.

We changed the route-selection model so that A* remained the underlying engine, while path weights shifted according to selected preferences:

Balanced speed & distance

🦊🛡️ Swiper-Safe

Avoids risky thief zones

🐒🍌 Boots Route

Easier, friendlier paths

🏔️🎒 Adventurous

Longer paths for discovery

What If the Road Suddenly Becomes Unavailable?

This was where the navigation system became genuinely dynamic. A route calculated at the start assumes the world is peaceful, but Dora's world is notorious for surprise obstacles. Bridges collapse, roads get blocked, and Swiper sneaks in.

CHAPTER 06 07
CHAPTER 06

Swiper Is Not a One-Time Event

Once we had basic rerouting, another question emerged: what happens if the alternative route gets blocked too?

We refused to hardcode fallback paths. Instead, we architected the system to repeatedly re-evaluate the graph whenever any obstacle state toggles:

1. Swiper blocks Path A 🦊
↓
2. Edge A cost set to ∞ (Blocked)
↓
3. A* recalculates from Dora's live node
↓
4. Obstacle cleared or updated → Recalculates dynamically

CHAPTER 07 08
CHAPTER 07

Navigation Should Understand the Journey

Finding a path was great, but we wanted DoraNav to understand the context of the adventure. This sparked the Backpack System.

Instead of displaying a static set of tools, the app examines route properties, biome, and terrain:

  • 🚣 Water Routes: Recommends raft, safety rope, life jacket
  • 🔦 Cave Biomes: Suggests high-beam flashlight & lantern
  • 🧤 Snowy Peaks: Suggests thermal parkas & climbing picks

"It was supposed to be a tiny fun feature. Somehow, Dora now has better, more intelligent travel preparation than most of us on our college trips."

The Contextual Backpack Item Drawer 🎒✨
